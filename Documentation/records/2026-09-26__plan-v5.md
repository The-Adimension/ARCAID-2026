# v5 and the Milestone 2 plan (2026-09-26)

Live Kaggle public LB at 2026-09-26 12:00 UTC: 3,343 teams. This team is **#334 at 3.59**. The 6.0 line is **#28** (6.04). 53 teams are at 5.0 or above, and 176 at 4.0 or above. The best public notebook is still 4.50, so there is no stronger public base to fork.

## Bottom line

- No change with published evidence reliably takes a Duck/Flash-Next fork from ~3.6 to 6+ in 4 days, so no "definitive win" is on offer.
- The largest lever the v3 logs support is throughput per game, and v3 wastes about 38% of its KV cache on text that carries nothing new. **v5 removes that waste without dropping any history.**
- v5 is cheap to validate: one save run on the same 6-game probe as v3, v4 and v4A.

## What the v3 logs show

- **The run is KV-bound.**
  - The model takes 81.8 GiB, which leaves a 5 GiB KV pool of 105,202 tokens.
  - In the 6-game probe, 3.07 requests ran and 2.65 waited on average.
  - Queue time (9,671 s summed) roughly equals decode time (10,004 s). Prefill is only ~10% of request time.
  - With 28 games in the rerun, far more requests wait.
- **Old reasoning is re-sent every turn.**
  - The template on `RadixArk/Qwen3.8-Flash-Next-NVFP4` renders the reasoning of every earlier assistant message, because `preserve_thinking` is undefined, which means true. Stock Qwen3 templates drop it.
  - Rendering v3's six prompt snapshots with that template and tokenizer gives **21.4K tokens** on average. vLLM measured **21.5K**, so the reasoning really is in the prompts.
- **What the prompt is made of** (tokens, mean of six snapshots):

  | Part | Share |
  |---|---|
  | Earlier reasoning | ~36% |
  | The same 14 instruction lines, repeated in every earlier USER turn | ~14% |
  | System prompt | ~17% (fixed) |
  | Everything else: actions, tool calls, results, world models, grid | the rest |

## The one change in v5

**`arc3_compact`** wraps urllib3's `HTTPConnectionPool.urlopen` in the notebook process, where `bm.run` plays every game. On each POST to `/chat/completions` it does two things:
1. **Drops old reasoning.** The reasoning of assistant messages older than the current turn and the newest 2 assistant messages is removed. Content, tool calls and tool results stay.
2. **Drops repeated instructions.** The 14 fixed instruction lines are removed from every USER message except the newest. Executed actions, state lines, the carried world model and the grid image stay.

Any exception leaves the request exactly as it was. The harness's own history trimming is untouched.

**Replayed on v3's six snapshots** (`presubmissions/v5/test_arc3_compact.py`, real template and tokenizer):

| Game | Tokens before | Tokens after | Ratio |
|---|---|---|---|
| ar25 | 24,214 | 16,384 | 0.68 |
| ft09 | 25,101 | 14,893 | 0.59 |
| lp85 | 21,157 | 12,767 | 0.60 |
| re86 | 19,245 | 14,684 | 0.76 |
| sb26 | 15,408 | 8,462 | 0.55 |
| vc33 | 23,236 | 11,932 | 0.51 |
| **Mean** | **21,393** | **13,187** | **0.62** |

**Why this is not v4A again:**
- v4A shrank prompts by lowering the harness budget. History fell from 23.9 to 17.8 messages, the model repeated moves, efficiency went from 0.72× to 2.26× human, and the score fell from 25.08 to 13.41.
- v5 keeps every message. Only old chains of thought and duplicated instructions go.

## What to expect (estimates, not measurements)

- **Rerun (28 games, KV-bound).**
  - Each request needs ~14.6K KV tokens instead of ~23K, so ~1.5× as many can run at once. `max_num_seqs` 8 and CUDA graphs to 32 already allow this.
  - At the v4A-measured elasticity (+18% running gave +11% tokens) up to linear scaling, that is +25–50% generated tokens per game, plus a ~38% cut in prefill.
- **Score.**
  - In the v3 probe, score rose ~0.8% per 1% more tokens in the 68K–100K band.
  - Estimated v5 true mean: ~4.4–5.1 against v3's ~3.6. This assumes dropping old reasoning is neutral for quality, which the save run tests.
- **Odds of a public score of 6 or more,** assuming a coefficient of variation of 0.27 per draw:

  | v5 true mean | One draw | Best of 4 draws |
  |---|---|---|
  | 4.4 | ~12% | ~40% |
  | 4.75 | ~19% | ~57% |
  | 5.1 | ~27% | ~72% |

  If v5 does not free throughput, the odds stay at v3's ~3% per draw.

## Considered and not recommended for 09-30

| Option | Why not |
|---|---|
| Larger KV pool | The v3 log already shows allocation failures at 5 GiB, and fp8 KV is blocked on this vLLM build. |
| Shorter context window (v4A) | Measured −47% on the probe. |
| Prefix caching | The pool can't hold 28 games' prefixes, and hybrid-model support in this build is unknown. |
| More MTP tokens | The profile is already a measured sweep winner. Gains at batch 3–6 are small. |
| Model swap or fine-tuning | Can't be validated before 09-30. |
