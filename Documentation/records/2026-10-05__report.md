# The jump to 30+: which notebook, and what actually caused it. Evidence report, 2026-10-05

Live data was read on 2026-10-05 between 10:16 and 10:45 UTC, through the Kaggle API and rendered Kaggle pages. Run data comes from this repo. Every number marked † is reproduced by `report-2026-10-05/luck_test.py` (output in `report-2026-10-05/luck_test.out`). Copies of the write-ups and threads used are in `report-2026-10-05/sources/`.

## Answer

- **The base notebook is [`dfranzen/arc-agi-3-milestone-2-solution`](https://www.kaggle.com/code/dfranzen/arc-agi-3-milestone-2-solution)**: Daniel Franzen's Milestone 2 entry, published 2026-09-30 08:21 UTC, with 518 votes.
  - 9 of the 14 highest-scoring public notebooks carry its harness patch byte for byte (same sha256 prefix `6fdcd1ae74`).
  - Two of the other three are the other Milestone 2 winners (lordhansolo, rellik13). They built the same core independently.
- **The jump itself is real, not luck.**
  - Teams that submitted a copy once score 25.8 ± 2.9 (n = 77)†.
  - The best pre-release public base (sheetu) has a best draw of 6.09. Our 21 draws never passed 4.17.
  - The gap is about 7 copy standard deviations, with hundreds of independent replications.
- **Most of the 30+ crowd is luck on that one notebook.**
  - Eight public draws of the identical code range from 21.01 to 29.08 (mean 25.88, SD 2.89)†.
  - Noise is 11–15% of the score at every level we can measure†. Scores of 30–34 are what best-of-k copies produce.
  - Expected-by-luck counts meet or exceed the observed counts at every threshold up to 34†.
- **Only a handful of teams are clearly above the copy envelope.**
  - Ranks 1–2 (Tufa Labs 55.89, Yi-Chia Chen 48.59) are outside it under any noise assumption.
  - Ranks 3–5 (39.30, 37.94, 37.54) are outside it only under the narrower assumption.
  - None of these teams has published code, so their extra edge can't be attributed.
- **What truly caused the jump is memory handling made affordable by inference engineering.** Each game gets more turns and keeps far more of its own history, reasoning included, in view, within the same 9 h on one GPU. Four parts:
  1. Prefix caching that works on Flash-Next's hybrid attention/Mamba layers. The old public base ran with prefix caching disabled.
  2. An FP8 KV cache, which gives a KV pool of about 1.0–1.4M tokens.
  3. A 64–128K harness context, trimmed in large blocks so the cached prefix survives, with history kept across levels.
  4. Admission limited to what the cache can hold (10–16 streams), so returning games don't find their prefix evicted.
- **The evidence for those four parts:**
  - All three independent winners converged on them.
  - The one clean single change on the hidden board (rellik13: FP8 KV plus longer history, nothing else changed) moved 14.49 → 22.53 (+55%, about 3× the noise).
  - lordhansolo: "The score closely followed the number of turns per game."
  - Our logs: the old base re-prefilled 10.5 prompt tokens per generated token. dfranzen re-prefills 2.1, at 94% cache reuse and a median prompt of 67K tokens†.
- **Not demonstrated on the hidden board** (inside noise, or never isolated):
  - the priority-scheduler formula, 10× image upscale, UNDO, level-transfer prompts, persistent functions, frame_diff, guards, game-over wording, knowledge packs;
  - adding advice text to prompts measured negative twice.

## 2. The base notebook

**What it is.** Tufa's Duck harness (commit `7652836`) plus one 8,405-line patch over 16 files; `tool_agent.py` alone gains 5,339 lines.

- **Model:** Qwen3.8-Flash-Next, using Intel's AutoRound W4A16 quantization with the BF16 PLE table offloaded to host RAM. Albucino's INT4 MTP draft provides 3-token speculative decoding.
- **Server:** Pennyroyal SGLang v2.5.3 with five patches:
  - Mamba prefix-checkpoint retention;
  - a speculative-state memory-budget fix;
  - low-M BF16 GEMM;
  - a Marlin scale-dtype fix;
  - shard prefetch.
- **Serving settings:**
  - Context: 131,072 in the harness and 139,264 on the server, with trims from about 118K down to about 59K.
  - KV cache: FP8 E4M3.
  - Streams: 10. All 110 games are live; a priority gate picks which 10 run.
- **Harness additions:**
  - animation frames as REPL variables, `frame_diff()`, difference images and game-over images, upscale 10;
  - UNDO exposed;
  - level-transfer and game-over prompts;
  - function retention for the whole game;
  - no-op and stale-state guards;
  - the structured world model switched off.
- **Licence:** a fork note calls the notebook Apache-2.0 (`amatlas/dfranzen-fork-d-prime`). Check the notebook page.
- **The author's own caveat** ([write-up](https://www.kaggle.com/writeups/dfranzen/arc-agi-3-milestone-2)): his observations are "practical experiment results rather than a complete controlled ablation study". He also writes that UNDO, action info, level-transfer guidance and persistent functions "produced a large improvement" together, but that this "does not isolate the contribution" of any one of them.

## 3. Luck versus real: the yardstick

**The same code gives a wide spread of scores.**

| Draw of the identical competition path | Score |
|---|---|
| dfranzen (author) | 27.89 |
| shiiin9, unchanged resubmission | 27.62 |
| skarin v1, submitted 10-02 / same version 10-03 | 27.80 / 21.01 |
| juliancamilovilla | 25.17 |
| svegio | 22.24 |
| manwithacat | 26.23 |
| bang1850 | 29.08 |
| **Mean ± SD** | **25.88 ± 2.89**† |

- **Independent cross-check:** 77 teams with exactly one submission score 25.81 ± 2.91 (p10 22.53, p90 28.97)†.
- **Noise scales with the score.** The coefficient of variation is 0.11 for our 8 Flash-Next draws (mean 3.07), 0.13 for rellik13's same notebook submitted 3× (5.02, 5.50, 6.42), and 0.11–0.15 for the dfranzen copies†.
- **What that means for testing:**
  - Two single draws must differ by about 30–40% before the difference clears 2 SD.
  - Detecting +8% (about +2 points at 26) at 80% power needs about 30 draws per arm. That is out of reach before 11-02.
- **Run-level variance is larger than game sampling alone predicts.**
  - dfranzen v3 played four replicates of the 25 public games in one job. Their means span only 1.87 points (45.6–47.5), while ten games individually swing 40 points or more (m0r0: 14, 71, 100, 0).
  - On the hidden board, identical code spans 8 points.
  - Part of the extra variance is infrastructure: runs that ended after 2–4 h during an outage (thread 744995).
- **The luck envelope.** For each team active since 10-01, I took up to 25 draws of the copy distribution (5 per day; an upper bound) and computed the expected count of teams at or above each threshold†:

  | Threshold | Expected by luck, SD 3.93 | Expected by luck, SD 2.91 | Observed |
  |---|---|---|---|
  | ≥ 30 | 550 | 427 | 171 |
  | ≥ 34 | 165 | 25 | 17 |
  | ≥ 35 | 93 | 8.3 | 11 |
  | ≥ 36 | 48 | 2.4 | 9 |
  | ≥ 38 | 10 | 0.1 | 3 |

  - Up to 34, luck alone explains the observed counts under either assumption.
  - At 36 and above, the narrow assumption leaves about 6–7 teams unexplained.
  - Per team, P(luck) is below 1e-7 for ranks 1–2 under both assumptions. For ranks 3–5 it is below 1e-3 narrow but 0.007–0.035 wide. From rank 12 down it exceeds 0.01 even narrow†.
- **Public games don't rank hidden-board changes.**
  - rellik13: "A notebook that scored 37 on my 25-game practice run got 9.98 on the leaderboard; one that scored 32 in practice got 13.40."
  - Our corpus: probe vs LB r = −0.32.
  - dfranzen's public mean is about 46.5, against about 26 on the hidden board.

## 4. What caused the jump, graded

**A. Causal and replicated**

1. **The bundle as a whole.**
   - Copies: 25.8 ± 2.9 (n = 77). Identical-path draws: 25.88 ± 2.89 (n = 8).
   - Baselines: best old public base 6.09; ours at most 4.17.
2. **Cache-resident long context:** prefix caching on hybrid layers, FP8 KV, large-block trims and bounded admission.
   - **Convergence:** 3 of 3 independent winners have all four; the old public bases have none (prefix caching off, 16–32K context, BF16 KV).
   - **Partial knockout:** `cihanatak/arc3-b32-reap-…-ctx48-r1` ran a 48K context with prefix caching off (`--no-enable-prefix-caching`, BF16 KV, 12 sequences, a REAP-pruned model) and scored 8.02. Long context without cache reuse stayed near the old band.
   - **Single change on the hidden board:** rellik13 14.49 → 22.53 (+55%). "Prompts, harness logic, model and sampling unchanged, so the effect comes from memory." Their logs showed the KV pool "91–97% full all run" and requests queued for cache space beforehand.
   - **Mechanism, in each winner's own words:**
     - lordhansolo: "the score follows the number of turns each game gets … I cannot confirm that any of these [harness] changes improved the score".
     - dfranzen: larger context helped "but only when the serving stack could reuse it efficiently".
   - **Our logs:** see section 5.
3. **Qwen3.8-Flash-Next with MTP decoding.** This is the earlier step: rellik13 went 0.99 → 3.81 (+285%), and dfranzen calls each model switch "substantial". It is a precondition, but the old base already had it, so it doesn't explain the 09-30 jump.
4. **Keeping the model's reasoning in history.** dfranzen: removing it "leads to a large regression". This already sits in Duck, so it isn't new in Milestone 2. The new part is that far more of it now stays in view.

**B. Plausible but not isolated** (single draws near the 30–40% bar, or no hidden-board number)

- **Dynamic compute allocation across games.** All three winners use some form of it, but:
  - D′ on dfranzen: mean 27.95 over 3 draws, +8% and not significant;
  - a scheduler on the old base (`shiiin9/duck-plus-ours`) scored 5.75, the old base's level;
  - rellik13 held it back because "games stagnate in their later stages".
- **Pinning each cleared level's rule in the prompt:** rellik13 7.14 → 9.96 (+39%, one draw).
- **Wang's sandbox, segmentation and prompts:** rellik13 9.96 → 13.40 (+35%, one draw).
- **Animation frames.**
  - The sheetu author measured 3.20 → 3.71 (+16%, one draw). dfranzen calls it his strongest perception gain in demo tests (tn36 needs it).
  - It was present on both sides of the jump, so it can't explain the jump.
- **UNDO, action info, level transfer and persistent functions.**
  - dfranzen: "large improvement" together, but "does not isolate".
  - rellik13's harness-fix bundle (UNDO rename, "Level restarted", deleting the ignore-the-bar line, animation frames): 13.40 → 14.49 (+8%), inside noise.
- **Switching off the structured world model:** dfranzen, demo tests only.

**C. No hidden-board support, or negative**

- **Higher image resolution.**
  - dfranzen calls 10× his biggest image gain in demo tests.
  - But rellik13 scored 22.53 at 4×, and reports that "higher-resolution board images" didn't work.
- **Adding advice text.**
  - rellik13: 6.42 → 4.16, and a level-start advice block 13.40 → 9.98. Their reading is that at a capped context, instructions push the agent's own history out.
  - Knowledge pack on dfranzen: 27.28, inside the copy band.
- **Fine-tunes and pruning.**
  - Swift 1.5: "no better per token and about 35% slower".
  - Pruning a quarter of the experts: "more room, worse play".
  - The REAP-pruned public notebook: 8.02.
- **Restarting a stuck level with a fresh context; temperature 1.0; ledgers** (rellik13; our ledger draw was 2.57).
- **Our own module stacking** (reset, ledger, prompts, stall, compact, wmreason): all draws in 2.57–3.59. No single step exceeded noise (`corpus/AGI-RUBIQ-CORPUS-2026-10-01.md`, O-02).

## 5. The mechanism in our own logs

dfranzen v1 played 10 public games for 25 min with 10 streams. Our sheetu run played 25 public games for 120 min with 16 sequences. These are public-demo save runs, one each; they are not hidden-set play.

| | sheetu (old base) | dfranzen v1 |
|---|---|---|
| Prefix-cache queries | 0 (caching disabled) | 94.2% of prompt tokens served from cache† |
| Prompt tokens prefilled per generated token | 10.5† | 2.1 (uncached only)† |
| Prompt size | ≤ 16K window | median 66.7K, p90 103.5K† |
| Aggregate generated tok/s | 257† | 616†, matching the 609 in his write-up |
| Same 10 games: levels cleared | 23, in 120 min | 40, in 25 min† |
| Same 10 games: mean score (excluding sb26) | 15.64 (17.07) | 36.56 (30.25)† |

- Per game, dfranzen generated about 93K tokens using about half the GPU-time share that sheetu's games had, and cleared more levels per token.
- Both effects point the same way: more turns, and each turn sees more of the game's own history.

## 6. What this means for us

- **Base.** An unchanged dfranzen copy is expected to land at about 26 (p10 22.5, p90 29). A second draw adds about +1.6 to the expected best (0.56 σ).
- **Don't A/B harness tweaks on the LB.** Effects under about 30% can't be seen in one or two draws.
- **Judge changes on low-variance mechanics at matched tokens.** Both lordhansolo and rellik13 recommend this: turns per game, generated tokens per game, cache reuse, and levels per million tokens.
- **Headroom is where the cause was:**
  - more turns and more retained history per game, by serving more tokens and keeping more context hot;
  - or a stronger model.
  - Prompt and perception additions so far measure as noise or negative.
- **Cheapest decisive test of this report:** run the dfranzen notebook unchanged except `LOCAL_ANALYZER_CONTEXT_WINDOW = 32K` with a proportionate drain.
  - If two draws stay at about 26, memory is not the cause.
  - If they fall toward 10–15, it is.
- **Open risks before 11-02:**
  - **Licence.** Is Qwen3.8-Flash-Next (Qwen Community License, not OSI-approved) prize-eligible? Thread 745079 has no host answer as of 10-05. Several dependency datasets list their licence as "unknown".
  - **Docker image.** Since 10-01 the default image is Python 3.13. The claim that reruns use the pinned image comes from a participant, not the host (thread 745654).
  - **Truncated runs.** Some runs ended after 2–4 h during an outage (thread 744995).

## What would falsify this

- **If unchanged dfranzen copies are seen at 34 or more** (on team boards, not notebook pages), the narrow envelope is wrong, and ranks 3–16 are luck as well.
- **If a prompt or perception change shows +30% or more across 3 or more hidden-board draws per arm**, tier C is wrong for that change.
- **If the 32K-context ablation in section 6 scores about 26**, the memory-handling explanation is wrong.
- **If a top-5 team publishes and its edge comes from fine-tuning rather than serving or memory**, the headroom ranking in section 6 changes.
