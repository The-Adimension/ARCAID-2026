## Reading

**Serving gained modestly:**
- Prompts shrank 27%, requests running rose 18% and requests waiting fell 59%.
- Generated tokens rose only 11%, because per-request decode got slower at the larger batch.
- Preemptions tripled (17 → 53), and there were 3 OOM warnings against 2 before.

**The agent lost far more than that:**
- With less history in context, the model repeats moves it has already tried:

  | Game | Level | Actions | Human baseline | Note |
  |---|---|---|---|---|
  | ar25 | L2 | 658 | 50 | v3 cleared it in 16 |
  | re86 | L4 | 398 | 108 | only 6 distinct actions |
  | sb26 | L2 | 557 | 28 | 52 distinct clicks, top ones repeated 60–71 times |

- Stall warnings fired 126 times, and banned actions passed straight through 1,532 times.
- Result: efficiency 0.72 → 2.26, levels 19 → 15, score −47% against v3.

**Setup took 1,350 s** (v3: 935 s, v4: 985 s). The competition budget re-fit absorbs this, but it is time taken from play.

## Verdict

- **Not submission-worthy.** v3 remains the best-evidenced version.
- **Implication for option B (fp8 KV cache).** B keeps the full context, so it avoids v4A's failure mode. But v4A shows that about 18% more concurrent requests bought only about 11% more generated tokens. B's throughput upside is therefore probably modest too, and it stays out of scope before 2026-09-30.
