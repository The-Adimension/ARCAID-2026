# v4 (unsubmitted) vs v3 (LB 3.59): evaluation from code and logs

## What changed (notebook diff)

- **v4 = v3 minus the `arc3_score` prompt block**: the scoring rule, time budget and click-target lines are removed.
- **Unchanged:** `arc3_batch.py` and `arc3_stall.py` (byte-identical), the budget re-fit, the teardown guard, the counters, and the serving profile `kv5-bf16-mtp3-c8-cg32`.
- **The notebook's stated reason:** "actions per decision 6.92 to 4.63, tokens per action 277 to 662". These are proxy metrics from an earlier run that is not in this folder.

- **Same number of levels, very different efficiency.** Both versions cleared 19 levels. v4 used about twice the actions per cleared level, and was less efficient on 6 of 6 games. The quadratic penalty on those extra actions accounts for the 35% lower score.

- **The notebook's "RHAE" diagnostic hid the drop:** it read 24.94 against v3's 26.13 and "WITHOUT sb26 29.37" against a 28.81 baseline. That diagnostic ignores efficiency. The real scorer went from 25.08 to 16.23.
- **Throughput is unchanged,** as expected from identical serving: 881,771 generated tokens, 9,262 s summed queue time, 14 preemptions.
- **Stall warnings still barely reach the model:** 44 were generated and the text appears in 2 transcripts. 18 actions were dropped, and 297 banned calls passed through.
- **Setup took 985 s** in this save run (v3's took 935 s). The budget re-fit absorbs it.

## Verdict

- **Do not submit v4 instead of v3.** On the only like-for-like evidence, removing the scoring and time lines roughly halved action efficiency and cut the probe score by 35%.
- **Caveat:** each version ran once, on 6 public games. The efficiency gap is consistent in direction (6/6 games), but the size of the drop is uncertain.
- **v3 remains the base.** Any new variant (for example, option A, the shorter context window) should start from v3 and be judged on the real `score.json` and on actions per human baseline, not on the completion-only diagnostic.
